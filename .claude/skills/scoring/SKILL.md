# Scoring rubric, growth score and scoring data

> Before writing any key below, run the Redis-safety checklist in CLAUDE.md (keys touched, read-modify-write, concurrent writers, rollback, admin-route `?confirm=YES` + stash + diff, recent Blob backup). Everything here was moved verbatim from CLAUDE.md; nothing was summarised away.

## Rubric (moved from CLAUDE.md Architecture)

### Scoring rubric v3 (Sep 2026): conviction + setup, never blended
The composite is a **33-pt CONVICTION score** (`SCORE_GROUPS` / `MAX_SCORE` in `app/lib/types.ts`): Long-term 4 · Research 6 (analystConsensus, researchMentions) · Fundamental 13 (growth scored FORWARD, `returnsMargins`, relative + historical valuation, leverage, cash-flow quality) · Company 7 · Management 3. The four technical categories (charting, SIA, BoostedAI, MarketEdge) are `SETUP_GROUP` — still stored on `stock.scores`, still edited on the stock page, but **never summed into the composite**; they feed the 0–10 setup grade in `app/lib/setup-grade.ts`, read BESIDE conviction (`actionFor()` gives the two-axis action). `researchCoverage` is retired (key kept for stored blobs only). Cutoffs live ONLY in `app/lib/rating-bands.ts` (26.5 / 23.5 / 19.5 / 16 on 33) and were quantile-calibrated from live data via `/api/admin/rubric-v3-calibration` — never ratio-scale them. Score-history entries carry `scaleMax`; anything differencing two entries must not compare across scales. Iterate `ALL_GROUPS` when the UI must show or edit every stored category, `SCORE_GROUPS` when it means the composite. Use `ZERO_SCORES` from types.ts instead of hand-listing keys.

### Rubric revision 7 (Sep 2026 prompt audit): growth is COMPUTED, not judged
`app/lib/growth-score.ts` computes the growth category from four FactSet metrics (forward sales growth, forward EPS growth, the 3–5y estimate, delivered 3-year growth), each ranked as a percentile inside the company's sector-playbook peer group (`pm:growth-bands`; folds into the GICS sector under 12 names), blended 30/30/20/20 and mapped to 0–3. A 3 needs the top ~15% of the group AND no metric below the group median AND ≥5% forward growth. A symmetric ±1 applies when the FY+1 consensus moved more than 3% in three months. The model receives the working in a `=== COMPUTED GROWTH SCORE ===` block and may move the result by AT MOST one point for a named reason; `/api/score` clamps anything further and attaches the full working to `explanations.growth.growthCalc` (shown by `GrowthMath` on the stock page; a compact copy rides on new `pm:score-history` entries as `growth`). No bands stored → growth parks as DATA GAP. Never reintroduce hand-set growth thresholds into the prompt. Other rev-7 rules: estimate revisions live ONLY in growth + analystConsensus; the DATA GAP rule is fill-first (web search) and direction-neutral; PM-logged notes are no longer sent to the model (the stock-page editor is a notebook); analyst OPINIONS (Morningstar moat / capital-allocation ratings, targets, the analyst's own estimates) never move a score, while company-reported `industryKpis` and `segments` from a filed report can; instruction text inside data formatters is part of `RUBRIC_HASH` (`FORMATTER_HASH_INPUT` in `rubric-version.ts`) — keep formatters descriptive and put rules in `scoring-prompt.ts`.

## Per-key detail (moved from CLAUDE.md)

- **`pm:score-history`** — **append-only** per-ticker log of composite score changes. Shape: `{ [ticker]: Entry[] }` where each `Entry` is `{ date, timestamp, total, raw, adjusted, scores }`. Written by the stock page's `handleRescore` flow (via `POST /api/kv/score-history`) once the fresh score has propagated into context. Same date-validation invariant as `pm:portfolio-snapshots`: POST rejects entries whose `date` is not today (server UTC). Read by the Score History tile on the stock page. Informational-only — not fed into alerts or composite math.
- **`pm:sia-history`** — **append-only** per-ticker log of SIA relative-strength readings. Shape: `{ [TICKER]: SiaHistoryEntry[] }` where each entry is `{ date, timestamp, smax?, percentile?, rank?, universeSize? }`. Written on every SIA CSV ingest (emailed path via `logSiaHistory` in `inbox-dispatch`, manual path via `POST /api/kv/sia-history`), scoped to **held names only** (Portfolio + Watchlist) — logging all 566 universe rows weekly would grow the key without serving the question it exists for. Same date invariant as `pm:portfolio-snapshots`: one entry per ticker per day, today only, and the FIRST reading of a day wins so a re-upload or an out-of-order batch can never rewrite history. Capped at 220 entries/ticker (~4 years weekly). Exists because `stock.sia` holds only the latest SMAX, and SMAX is a 0-10 integer too coarse to show drift — a name can slide from the 91st to the 62nd percentile and still read "10". Read by `computeChangeEvents` to raise the `relative-strength` event (`THRESHOLDS.siaPercentileDrop`). **Monitoring only — it NEVER feeds a score**; `mapSmaxToRelativeStrength` remains the sole path from SIA into the composite. **BACKED UP** (deliberately not in the backup exclude list) — losing it loses the trend evidence.
- **`pm:growth-bands`** — peer-group growth distributions the COMPUTED growth score ranks against (`app/lib/growth-score.ts`): for every S&P 500 + TSX 60 constituent, forward sales growth, forward EPS growth, the 3–5y growth estimate and delivered 3-year growth, winsorised and sorted per sector-playbook group and per GICS sector (`GrowthBands`). Written ONLY by `GET /api/admin/growth-band-calibration?confirm=YES` (dry-run is the default and lists every constituent + exclusion so the numbers can be audited against a FactSet terminal first); the prior value is stashed at `pm:growth-bands.pre-<ts>` before every overwrite, and the route refuses to store a partial pull. Read-only everywhere else. Regenerable — safe to nuke (growth then parks as DATA GAP until the route is re-run), but a re-calibration moves growth scores, so treat an overwrite as a scoring change. Refresh roughly once a year.
- **`pm:growth-bands-detail`** — the per-company audit trail behind `pm:growth-bands`: for every calibration constituent, the raw FactSet inputs (the formulas in `GROWTH_SOURCE_FIELDS`, `app/lib/growth-score.ts`), the four derived growth metrics and any exclusion reasons (`GrowthDetail`). Written ONLY by the calibration route together with the bands (`?confirm=YES`; prior value stashed at `.pre-<ts>`), read ONLY by `GET /api/growth-bands/detail`, which recomputes every company's percentiles / blend / base score with `computeGrowthScore` — the same function `/api/score` uses — for the `/methodology/growth-data` page (worked examples + CSV export). Regenerable — safe to nuke (the page shows a "run the calibration" notice). Keep it in step with the bands: the page flags a mismatch in `calibratedAt`.
- **`pm:edgar-ticker-map`** — cached SEC ticker→CIK mapping (the `company_tickers.json` file from sec.gov). Refreshed lazily every 7 days on first call after expiry. Pure cache (no user input). Safe to nuke (next call rebuilds it). Required by `app/lib/edgar.ts` for ticker-to-CIK resolution before fetching XBRL company facts.
- **`pm:edgar-submissions:{paddedCik}`** — cached SEC submissions metadata for a CIK (`data.sec.gov/submissions/CIK{paddedCik}.json`). Includes the `sic` code which drives industry classification (bank/insurance/REIT/SaaS/biotech/energy/etc.) for the EDGAR concept registry. Refreshed lazily every 7 days. Pure cache. Safe to nuke. Used by `app/lib/edgar-industry.ts`.
- **`pm:edgar-form4:{TICKER}`** — per-ticker cached SEC Form 4 insider-activity summary (officers / directors / 10%+ owners). Aggregates the last 90 days of OPEN-MARKET trades only (codes P=Purchase, S=Sale); deliberately excludes RSU grants/vests, option exercises, tax-withholding sales, and gifts. Refreshed lazily every 24 hours per ticker. Drives the `ownershipTrends` scoring category. Pure cache. Safe to nuke. Required by `app/lib/edgar-form4.ts`.
- **`pm:edgar-facts:{TICKER}`** — per-ticker cached XBRL company facts from `data.sec.gov/api/xbrl/companyfacts/CIK{cik}.json`. Refreshed lazily every 24 hours on first call after expiry. Returns the full taxonomy of US-GAAP and DEI concepts for that issuer (every line item from every filing, ~5MB per ticker for large filers). Pure cache. Safe to nuke individual entries; next score will refetch. **Requires the `SEC_USER_AGENT` env var** to be set (the SEC rejects requests without a User-Agent identifying the caller via a contact email).
