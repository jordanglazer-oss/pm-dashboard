# AI watchers data

> Before writing any key below, run the Redis-safety checklist in CLAUDE.md (keys touched, read-modify-write, concurrent writers, rollback, admin-route `?confirm=YES` + stash + diff, recent Blob backup). Everything here was moved verbatim from CLAUDE.md; nothing was summarised away.

## Per-key detail (moved from CLAUDE.md)

- **`pm:agent-settings`** / **`pm:agent-spend:<YYYY-MM>:*`** / **`pm:agent-calls`** — the AI watchers (Nov 2026, `app/lib/agents/`). Watchers run ONLY on `ANTHROPIC_AGENTS_API_KEY` (own Anthropic workspace, $100/month limit) through `agentCall()` in `app/lib/agents/gateway.ts` — the one file allowed to read that key (ESLint `no-restricted-syntax` rule in `eslint.config.mjs`); every existing feature stays on `ANTHROPIC_API_KEY` via `new Anthropic()`. The gateway refuses (before spending) when the key is missing (never falls back to the main key), equals the main key, watchers are paused, or this call's worst case would push the month past the $90 stop. `pm:agent-settings` = `{ models: {watcherId: "haiku"|"sonnet"} (overrides only), off?: {watcherId: true} (per-watcher switch on Monitor: the gateway refuses its calls and its rule-only flags are not raised), paused? }`, read-merge-write via `POST /api/agents/settings`, GET never seeds. Spend = atomic `INCRBYFLOAT` string counters per UTC month (`:total`, `:usd:<watcher>`, `:calls:<watcher>`) — strings so the backup's GET reads them; `pm:agent-calls` = last 200 calls. Watchers monitor and suggest only: they never trade, change weights or change scores. `GET /api/agents/status` is read-only. Losing these only resets the month's counter (the Anthropic workspace limit still holds) and the model overrides.
- **`pm:agent-flag:<id>`** — the watchers' flag log (`app/lib/agents/flags.ts`): ONE JSON-string key per flag (`{ id, watcher, priority, ticker?, title, detail, suggestion?, evidence?, dedupeKey?, status: open|acted|dismissed, thread[], model? }`), listed by SCAN — one key per flag so two watchers raising at once can't overwrite each other. Since Phase 2 a flag may carry `factCheck` (`app/lib/agents/fact-check.ts`, agents key, Haiku: supported / partly / unsupported / skipped) — the earnings-comparison watcher fact-checks every finding against its preview + recap before raising it and does NOT raise an `unsupported` one (the run keeps it); a gateway refusal returns `skipped` and the flag is raised as before. Created ONLY server-side by `raiseFlag` (an open flag with the same `dedupeKey` is refreshed in place, not duplicated); the PM's Act / Dismiss / Reopen / note goes through `POST /api/agents/flags/<id>` (read-modify-write of that one key). There is deliberately no client create route and nothing deletes a flag. Open flags feed the Brief action queue as source `agent` (resolved on `/monitor`, not via `pm:action-state`). **BACKED UP.** Losing them loses the record of what was raised and how the PM responded.
- **`pm:agent-run:holdings-watch:<date>:<TICKER>`** + **`pm:agent-run:holdings-day:<date>`** — the holdings watch (Phase 3, `app/lib/agents/holdings-watch.ts`): weekday cron `/api/cron/holdings-watch` (21:45 UTC) or Monitor's "Run today's check now" (`POST /api/agents/holdings-watch`). Every Portfolio holding that moved ≤ −4% / ≥ +5% is classed in CODE against beta × market (SPY, or ^GSPTSE for Canadian names) and its SPDR sector ETF — market / sector / fund moves are logged and stop ($0). A company move (≥ 3 pts unexplained) goes to the `triage` watcher (Haiku) with the free sources (FactSet alerts ≤ 2 days, a FRESH SEC submissions read — not the 7-day cache — and the earnings date), then, if still unexplained and ≥ 5 pts, `holdings-investigate` (Sonnet, ≤ 3 web searches, ≤ 5 per run) whose finding is PROVISIONAL. Flags only when a pillar is touched or a large move stays unexplained; fact-checked first (unsupported → recorded, not flagged). Any new FactSet alert for the name runs `reconcileHoldingsEvents` (`after()` in inbox-dispatch, `reconcile` watcher, Haiku): confirmed → a quiet note on the flag; corrected → note + a medium `reconcile` flag. One key per event (180-day expiry) so the cron and a reconcile never overwrite each other. Reads pm:stocks / pm:position-theses / pm:street-takeaways READ-ONLY; never writes book data. Safe to lose (monitoring record only).
- **`pm:agent-state:stance`** — the stance watch + hedge window's last reading (Phase 4, `app/lib/agents/stance-watch.ts`): `{ date, at, signals, signalText, hedgeWindow, changes, flagIds }`, overwritten each run by its ONLY writer `runStanceWatch` (weekday cron `/api/cron/stance-watch` 22:00 UTC, or Monitor's "Check now" → `POST /api/agents/stance-watch`). Rule readings (regime label, pending flip, VIX band, breadth from the PM's manual entry, the brief's hedging call, hedges expiring ≤ 21 days) are compared with the prior run; a change → one `stance-watch` flag (Haiku writes the read; plain text if the gateway refuses). The hedge window (cheap M3 premiums ≤ 35th pct · VIX3M ≤ 60th pct of history · policy sentiment gate open · ≥ 1 warning sign) is decided in CODE (`hedgeWindowFrom`) and flagged once when it OPENS (`hedge-window`). First run records a baseline and flags nothing. Reads pm:market / pm:brief / pm:hedges / pm:market-regime READ-ONLY (a regime cache > 6h old is refreshed via `refreshMarketRegime`). Safe to nuke (next run re-baselines silently).
- **`pm:agent-state:manager-watch`** — the quarterly Thematic-fund review (Phase 4, `app/lib/agents/manager-watch.ts`): `{ quarter, at, funds: { SYM: snapshot }, baseline, reviews, usd }`, written ONLY by `runManagerWatch` (from the stance cron when the quarter is unreviewed, or Monitor's "Review funds now" → `POST /api/agents/manager-watch`). Plain rules on `pm:stocks[].fundData` (fund vs category 1/3/5y — sustained = ≤ −1.5 pts/yr on 3y AND 5y; fee, category and star-rating change vs the prior quarter's snapshot); a tripped fund gets a `manager-watch` read (Haiku) and a flag. Reads pm:stocks / pm:pim-models READ-ONLY. Safe to nuke (loses only the fee/category comparison baseline).
- **Theme review conversations (Phase 5)** — `app/lib/agents/theme-review.ts`. After the holdings watch (same cron), `runThemeWatch` reviews a theme when SPY ≤ −2% / QQQ ≤ −2.5% (themes ≥ 10% of non-Core) or its members fall ≥ 3 pts more than SPY on average; Themes page "Review now" → `POST /api/agents/theme-review`. The `theme-review` watcher (Sonnet) raises a flag with `conversation: { kind: "theme", themeId, trigger }`; `POST /api/agents/flags/<id>/reply` adds the PM's note and the watcher's answer to the thread (context rebuilt fresh each turn). Acting on / dismissing a theme-review flag (or any flag WITH a note) APPENDS an entry to `pm:decision-journal` (`app/lib/agents/journal.ts`, read-merge-write, keeps every entry and unknown field); the next review reads the theme's last journal entries. Writes only flags + journal appends.
- **`pm:agent-memo:<YYYY-MM-DD>`** — the Sunday memo archive (Phase 5, `app/lib/agents/sunday-memo.ts`): one JSON-string key per memo `{ date, at, headline, items[5-10], model, usd, emailed }`, written ONLY by `writeSundayMemo` (cron `/api/cron/sunday-memo` Sundays 22:00 UTC, which also queues it to ALERT_EMAIL_TO via pm:mail-outbox; or Monitor's "Write now" → `POST /api/agents/sunday-memo`, no email). Facts only from what is on file (flags, holdings events, stance, weak pillars, earnings dates, themes, hedges, fund review) — no web search. **BACKED UP.**
- **`pm:agent-run:earnings-compare:<id>`** — one JSON-string key per earnings-comparison run (`app/lib/agents/earnings-compare.ts`): the recap + preview it compared, the watcher model's answer and, until `shadowUntil` in the registry, the shadow model's answer side by side, plus the flag it raised. 180-day expiry; listed by SCAN on Monitor. Triggered after the response when a new `metrics` recap is filed (`after()` in inbox-dispatch — never fails the ingest) or by Monitor's "Compare latest results now" (`POST /api/agents/earnings-compare`). Reads previews / takeaways / theses / stocks READ-ONLY. Safe to lose (comparison-period evidence only).
