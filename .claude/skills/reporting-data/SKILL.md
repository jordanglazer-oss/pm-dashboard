# Client reporting data

> Before writing any key below, run the Redis-safety checklist in CLAUDE.md (keys touched, read-modify-write, concurrent writers, rollback, admin-route `?confirm=YES` + stash + diff, recent Blob backup). Everything here was moved verbatim from CLAUDE.md; nothing was summarised away.

## Per-key detail (moved from CLAUDE.md)

- **`pm:fund-one-pagers`** — client "why we own it" one-pagers per fund / ETF in the PIM model (Nov 2026, `app/lib/fund-one-pagers.ts`, page `/funds`, print view `/print/fund/<SYM>` outside the dashboard group): `{ pagers: { SYM: { headline, whyWeOwn, manager, process, role, record, fees, risks, talkingPoints, watch (internal, not printed), sources, aiDrafted, signedAt, history ≤6 } } }`. Written ONLY by `POST /api/fund-one-pagers` (PM signs one symbol, read-merge-write). `POST /api/fund-one-pagers/draft` (main key, Sonnet + ≤5 web searches) writes nothing; figures come only from `pm:stocks[].fundData`. English only. **BACKED UP.**
- **PM Monthly facts** (Nov 2026, `app/lib/pm-monthly-data.ts`, `GET /api/pm-monthly/facts?month=`, page `/pm-monthly`) — READ-ONLY: month model returns (pm:pim-performance + pm:sleeve-performance), index returns, contributors / detractors (book returns from the ledger's core / thematic / alpha series; weight in class at CURRENT model weights × month C$ total return — approximate, labelled), the month's decisions (trade log via `collapseTrades`, model versions, journal) and outlook inputs from pm:brief / pm:market-regime. Stores nothing.
- **`pm:pm-monthly-drafts`** — the PM Monthly client update per month in English + French (`app/lib/pm-monthly-drafts.ts`): `{ months: { "YYYY-MM": { en, fr, notes, aiDrafted, sources, updatedAt, history ≤5 } } }`, text in a plain "## heading / ### sub-heading / blank-line paragraph" convention. Written ONLY by `POST /api/pm-monthly` (save ONE month, read-merge-write, prior text kept in history). `POST /api/pm-monthly/draft` (main key, Sonnet + ≤5 web searches for the month's backdrop, then the French translation) and `POST /api/pm-monthly/translate` write nothing; house style = the Aug–Oct 2026 emails in `app/lib/pm-monthly-style.ts`; the drafting model receives the month's facts in WORDS only (`factsBlock` in `pm-monthly-write.ts`: directions, ranked areas — sectors / themes / sleeves — trades, rebalance days, theses for names bought, reasons for names sold, acted flags, weekly memos; any stray `n%` is scrubbed) and must never write a return figure of any kind (PM rule, Nov 2026); the page lists every sentence containing a % for the PM to check. `GET /api/pm-monthly/docx?month=&lang=` builds a Word file from the SAVED text with `app/lib/docx-lite.ts` (no dependency). **BACKED UP.**
- **`pm:client-report-analysis-cache`** — hash-gated cache of the Anthropic-generated "Where you are now / Recommendations / Summary" bullets for the Client Report PDF (`{ hash, result }`). Same pattern as the upticks scrape: `/api/client-report-analysis` POSTs the full portfolio comparison payload (client holdings, model holdings, allocations, performance, per-ticker MERs, optional brief context). The hash is computed over a canonicalized projection so order-independent. `force: true` bypasses the cache when the user hits "Regenerate". Safe to nuke (worst case: the Generate button re-spends one Anthropic call on the next click).
- **`pm:client-report-bullets-cache`** — hash-gated cache of the Anthropic-generated "Portfolio Highlights" talking points for the Client Report (`{ hash, result }`, `result = { bullets: string[], generatedAt }`). Distinct from `pm:client-report-analysis-cache`: those describe the CLIENT'S portfolio vs the model, these describe the MODEL alone (broad index exposure, diversification/breadth, blended MER, risk posture) and never name an individual position — they're written to be pasted into a client presentation. `/api/client-report-bullets` receives only asset-class / sector / geography / breadth-count / fee / risk aggregates — no tickers, no holding names, no client data. The Client Report page ALWAYS `await refetch()`s live report data before POSTing, so bullets can't be written off a stale snapshot; the generated copy is stored alongside a client-side fingerprint of those inputs in `pm:client-portfolio.presentationBullets`, and the UI flags "regenerate" when the live numbers drift from that fingerprint. `force: true` bypasses the cache. Safe to nuke (worst case: one Anthropic call on the next click).
