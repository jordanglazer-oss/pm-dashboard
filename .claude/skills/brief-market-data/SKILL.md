# Brief, market and hedging data

> Before writing any key below, run the Redis-safety checklist in CLAUDE.md (keys touched, read-modify-write, concurrent writers, rollback, admin-route `?confirm=YES` + stash + diff, recent Blob backup). Everything here was moved verbatim from CLAUDE.md; nothing was summarised away.

## Per-key detail (moved from CLAUDE.md)

- **`pm:regime-history`** — **append-only** daily log of the regime engine's read (`app/lib/regime-history.ts`): `{ rows: RegimeHistoryRow[] }` ascending by Eastern date, each row = `{ date, computedAt, rawLabel, label, weightedScore, score100, riskOn, riskOff, total, signals: {name→direction}, horizons: {tactical,cyclical,structural}, spx, vix }`. Written ONLY by `computeFromYahoo()` in `market-regime-refresh.ts` (the 30-min route recompute + nightly cron); one row per weekday, today only, same-day recomputes REPLACE today's row, past rows never touched, capped at 1500. Two jobs: (1) **hysteresis** — `composite.label` only follows `composite.rawLabel` after `HYSTERESIS_CONFIRM_DAYS` (3) consecutive sessions read the same way, so one bar can't flip the canonical label (the pending flip is exposed as `composite.pending`); (2) **validation** — `spx` per row makes "did Risk-On precede better forward returns?" answerable from our own data, the prerequisite to changing any signal/weight/threshold with evidence. `GET /api/kv/regime-history` is read-only; there is deliberately no client write path. **BACKED UP** (not in the exclude list) — losing it loses the evidence base and resets hysteresis (harmless: the next refresh commits the raw label).
- **`pm:action-state`** — the PM's done / snoozed marks on the Brief action queue: `{ [actionId]: { status: "done"|"snoozed", at, until? } }`. Managed by `/api/kv/action-state` (GET, POST one entry, read-merge-write, entries older than 45 days pruned on write). Action ids are date-scoped or event-scoped, so a stale mark can never hide a new item. Losing it only re-surfaces already-handled items.
- **`pm:deployments`** — user-owned log of the days the monthly client-cash installment ACTUALLY went in (`app/lib/deployments.ts`): `{ deployments: [{ id, date, month, portion: "full"|"half", note?, loggedAt, voided?, brief: { action, score } | null }] }`. Each entry snapshots what the brief called that day so the timing record stands alone. Two readers: the morning brief (the log itself, `DeploymentLog`, renders in the Brief decision panel's Cash cell — `CashCell` in `brief/SummaryTop.tsx`; once a month is fully logged the brief swaps to a system-prompt variant with the cash rubric and `cashDeploymentCall` field removed until the 1st — read-only) and the Cash Deployment tile's timing record (graded on the fly against SPY closes across that month's 1st–20th window; nothing about the scorecard is stored). Managed by `/api/kv/deployments`: GET returns `{deployments: []}` on a missing key and never seeds; POST adds ONE entry or voids ONE entry by read-merge-write — **there is deliberately no whole-array write and no delete**, so a stale tab cannot roll the log back. Back-dating is limited to the current or previous month. **BACKED UP** (not in the exclude list). Losing it loses the timing history and makes the brief resume its cash call for the current month.
- **`pm:hedges`** — user-owned ledger of ACTUALLY-IMPLEMENTED hedge positions (strike, premium, tenor, entry spot, expiry, contracts, status active/closed). Ground truth for whether the book has protection on: the morning brief reads it and only recommends `hedgingCall.action = "HOLD"` when ≥1 active (non-expired, non-closed) position exists — with none on the books the call is coerced to ADD/SKIP (prompt guardrail + deterministic HOLD→SKIP backstop). Managed by `/api/kv/hedges` (GET; POST MERGES by id — body rows are added or replace the stored row with that id, stored rows the body lacks are kept, so nothing is ever dropped; the Brief sends only the row it changed) and the Brief Hedging tile's log/close UI; helpers in `app/lib/hedges.ts` (`isActiveHedge`, `describeHedge`, `realizedPnlUsd`). Never seed/clobber — GET returns `{hedges:[]}` on miss. Losing it means the brief reverts to assuming unhedged.
- **`pm:fundstrat-levels`** — per-note support / resistance / target levels extracted from Newton + Lee notes (`app/lib/fundstrat-levels.ts`): `{ notes: { "<author>|<YYYY-MM-DD>": { textHash, extractedAt, levels[] } }, lastFailAt? }`. Written ONLY by `GET /api/fundstrat-view` — one small call covers only notes from the last 28 days not yet extracted (or re-saved with new text), read-merge-write, pruned past 45 days, a failed call backs off 6h. The panel shows the newest level per (author, instrument, kind), so a level stays until a newer note replaces it; faded after 14 days, dropped after 28. Derived data — safe to nuke (notes still in the 30-day history are re-extracted; older level memory is lost).
- **`pm:portfolio-snapshots`** — **append-only** daily history of sector breakdowns and top holdings per (date, group, profile). Past-dated writes are rejected by the route. Used for trend analysis; losing it means losing all historical drift data.
