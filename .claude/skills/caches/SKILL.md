# Regenerable caches and retired keys

> Before writing any key below, run the Redis-safety checklist in CLAUDE.md (keys touched, read-modify-write, concurrent writers, rollback, admin-route `?confirm=YES` + stash + diff, recent Blob backup). Everything here was moved verbatim from CLAUDE.md; nothing was summarised away.

## Per-key detail (moved from CLAUDE.md)

- **`pm:market-regime`** — cached output of `/api/market-regime` (Yahoo-derived regime snapshot: SPX 10M trend, RSP/SPY breadth, sector ratios XLY/XLP & XLK/XLU & MTUM/USMV, cross-asset VIX/DXY/^TNX/CL=F, global ^STOXX & ^N225, plus composite Risk-On/Neutral/Risk-Off label). Shape: a single JSON blob matching `MarketRegimeData` in `app/lib/market-regime.ts`. Since Sept 2026 the composite is a FIXED slate (every signal votes, neutral included — never let a neutral signal drop out of the denominator again, that is what made the label flip on quiet days), rolled up as the horizon-weighted score from `horizons.ts` (`composite.weightedScore` / `score100`), with `composite.label` hysteresis-smoothed via `pm:regime-history` and `composite.rawLabel` the unsmoothed read. FRED-derived votes (ISM / credit / curve) fall back to the cached readout when a fetch fails so the slate stays fixed. Pure cache (no user input) — recomputed on GET when older than 30 minutes or when `?refresh=1` is passed. On Yahoo failure the route falls back to the cached value (even if stale) rather than blanking. Safe to nuke (next GET rebuilds it).
- **`pm:market-drivers`** — cached output of `/api/market-drivers` (`app/lib/market-drivers.ts`): cap-weighted contribution of every S&P 500 + TSX 60 constituent (lists in `factor-constituents.ts`) to its index's 1d/1w return, per-sector rollups with leaders/laggards, and 1d/1w/1m/3m returns for the sector + industry ETF universe — one batched FactSet cross-sectional pull (`P_TOTAL_RETURNC(-1D,0)` etc. + `FG_MKT_VALUE` + `FG_GICS_SECTOR`). Feeds the Brief summary's "Market drivers" zone and the regime sector map. Pure regenerable cache — rebuilt by the nightly backup cron and lazily on GET when older than 20h (`?refresh=1` forces); on a failed rebuild the stale cache is served with `error` set, and an empty build never overwrites a good snapshot. Safe to nuke.
- **`pm:earnings-dates`** — 24h cache of Yahoo next-earnings dates for tickers NOT in `pm:stocks` (the Suggested watchlist names the Brief calendar shows). `{ [TICKER]: { date, fetchedAt } }`, read-merge-write. Pure cache. Safe to nuke.
- **`pm:brief-prevday`** — compact digest (regime, verdict, bottom line, hedging + cash calls, dates) of the most recent brief from a PREVIOUS Eastern day. Written by `/api/morning-brief` whenever it finds a prior-day brief in `pm:brief` at generation time; read when the brief is REGENERATED same-day so the "since last brief" comparison stays anchored to the previous trading day instead of the earlier same-day run. Regenerable cache — safe to nuke (worst case: one same-day regeneration compares against the earlier same-day brief, clearly labeled).
- **`pm:fundstrat-view-cache`** — hash-gated AI summary of the latest Newton + Lee notes for the Brief's Fundstrat view (`GET /api/fundstrat-view`, reads `pm:strategist-history` read-only; one Sonnet call only when a note changes, `?refresh=1` forces; stale cache served on failure). Pure cache — safe to nuke.
- **`pm:vol-anchor`** — cached long-horizon vol anchor for the hedging read (`getVolAnchor` in `app/lib/hedging.ts`): current ^VIX and ^VIX3M levels ranked as percentiles of their FULL Yahoo history (~35y / ~16y). The multi-regime guard against the hedging ledger's short collection window — "premium at the 20th percentile of our ledger" is only meaningful alongside "and VIX3M is at the Nth percentile of 16 years". Refreshed lazily every 24h. Pure cache — safe to nuke.
- **`pm:risk-analytics`** — cached output of `/api/risk-analytics` (book-level risk lens: covariance risk contributions, correlation clusters, beta-weighted look-through sector exposure, historical stress replays — computed from 1y of Yahoo daily closes for the Portfolio bucket). Pure regenerable cache (reads pm:stocks/pm:market READ-ONLY); recomputed on GET when older than 6h or `?refresh=1`. On compute failure the route serves the stale cache rather than blanking. Safe to nuke.
- **`pm:fund-data-negative:{TICKER}`** — negative cache for tickers `/api/fund-data` confirmed don't have data (Morningstar IDs Yahoo can't resolve, delisted symbols, insurance variable annuity funds, etc.). Auto-expires after 7 days; subsequent calls return a fast `404 { cached: true }` instead of paying another multi-second Yahoo timeout. Force a re-attempt with `?force=1`. Without this, every Client Report load and PIM model refresh would re-pay the slow lookup for every untranslatable ticker on every page open. Safe to nuke individual entries.
- **`pm:ratelimit:auth:*`** — per-IP login-attempt counters (auto-expire every 60s). Safe to ignore; not user data.
- **`pm:upticks-scrape-cache`** — hash-gated cache of the Anthropic vision parse of the Newton's Upticks screenshot (`{ hash, entries, analyzedAt }`). Mirrors the JPM-flows caching pattern in `app/api/morning-brief/route.ts`: the Refresh button in Research always POSTs the current upticks attachments to `/api/upticks-scrape`, but the route only spends Anthropic tokens when the image fingerprint changes. Safe to nuke (worst case: one re-scan on next Refresh).
- **`pm:research-scrape-cache:{source}`** — hash-gated cache of the Anthropic vision parse for the four non-Newton research sources, where `{source}` is one of `fundstrat-top` / `fundstrat-bottom` / `fundstrat-smid-top` / `fundstrat-smid-bottom` / `rbc-focus` / `rbc-us-focus` / `seeking-alpha-picks`. Same `{ hash, entries, analyzedAt }` shape as the upticks cache and same semantics: `/api/research-scrape` only spends Anthropic tokens when the image fingerprint for that specific source changes (or `force: true` is passed). Each source caches independently so refreshing one doesn't invalidate the others. Safe to nuke individual keys (worst case: one re-scan on next Refresh for that source).
- **`pm:factor-universe`** / **`-progress`** / **`-names`**, **`pm:factor-scores`** — RETIRED Nov 2026 with the shadow factor model, Radar and Factor Lab (code removed; the weekly build and its Apps Script ping are gone). Pure caches: nothing reads or writes them; safe to nuke. Do not reintroduce.
- **`pm:factor-history`** — RETIRED Nov 2026 (no longer written or read). Kept in Redis and the nightly backup as the historical record of the shadow factor read-outs; do not clobber.
